# App Flow Document for compose-multiplatform-music-player

## Onboarding and Sign-In/Sign-Up
When a new visitor arrives at the application’s root URL, they land on a simple welcome page that invites them to sign in or sign up. The landing page displays brand colors, a brief introduction, and two prominent buttons labeled “Sign In” and “Sign Up.” Clicking the “Sign Up” button brings the user to `/sign-up`, where they enter an email address and a password. The form validates the email format and checks that the password meets minimum length requirements. Once they submit, the app calls the `better-auth` API route, creates their account in the PostgreSQL database, and then redirects them automatically to the dashboard. If an existing user clicks “Sign In,” they land on `/sign-in` and supply the same credentials. On success, the app sets a secure session cookie and sends the user to the dashboard. If the credentials are wrong, an inline error message appears. There is also a link to recover a forgotten password. Clicking that link opens a password recovery form where the user enters their email. The system sends a reset link to that address, and clicking the link in the email brings them to a reset page where they choose a new password. Once reset, they can sign in normally. A sign-out button lives in the dashboard header; clicking it clears the session and returns the user to the landing page.

## Main Dashboard or Home Page
After a successful login, the user lands on `/dashboard`. The layout consists of a persistent header, a collapsible sidebar on the left, a main content area in the center, and a fixed footer. The header includes a search input that allows live searching of songs, albums, or artists. The sidebar lists the user’s personal playlists and library sections, and a button at the bottom toggles between light and dark themes. The main content area initially shows a grid of recommended album or artist cards along with an interactive listening history chart. Each card displays an image, title, and brief info. Below these cards, a summary table highlights the user’s recently played tracks. The footer remains visible at all times and contains the global audio player with play/pause controls, skip buttons, a progress bar, and volume control. From this dashboard, the user can click any sidebar link or any card to navigate deeper into their library, or use the search box to jump directly to results.

## Detailed Feature Flows and Page Transitions
When the user clicks a playlist name in the sidebar, the application navigates to `/dashboard/playlists/[id]`. The page fetches the track list for that playlist via an API route and displays it in a sortable table. Each row shows track title, artist name, and duration. Clicking on any row starts playback of that track in the global player while leaving the user on the same page. If the user clicks on an album card in the main dashboard or a search result for an album, the app routes to `/dashboard/albums/[id]`. This page follows the same table layout to list tracks, but it also shows a larger album cover and description. Clicking an artist card or name navigates to `/dashboard/artists/[id]`, displaying that artist’s top tracks and albums in separate sections. The header search input allows the user to type keywords and see dynamic results in a dropdown. Selecting a result directly navigates to the matching playlist, album, artist, or track page. In the case of a track result, it opens a track detail overlay where the user can see lyrics (if available) and add the track to an existing playlist via a dropdown menu.

## Settings and Account Management
Users can access their personal settings by clicking their avatar in the header and choosing “Settings.” This takes them to `/dashboard/settings`, where a simple form shows their current email and display name. They can update these fields and submit; the app calls an API route to update the database and then shows a confirmation banner. Below the basic information, they see toggles for notification preferences—such as receiving emails about new features or playlist activity. There is also a section to change the password by entering the current password and a new one. Submitting that form triggers a secure password update in `better-auth` and confirms success. At the bottom of the settings page, there is a button labeled “Back to Dashboard” that returns the user to the main library view.

## Error States and Alternate Paths
If the user attempts to access `/dashboard` or any protected route without a valid session, the app redirects them to `/sign-in` and displays a message saying “Please sign in to continue.” If the user submits invalid data on any form—such as a malformed email, a too-short password, or a blank playlist name—the form shows inline validation errors next to the affected fields. Network problems trigger a full-screen message that says “Network connection lost” with a retry button that attempts to reload the current page. On server-side errors, such as a database failure, the user sees a friendly error page with a simple apology and a button labeled “Go Home” that returns them to the landing page. If a nonexistent resource is requested—for example, a playlist ID that doesn’t exist—the app displays a “404 Not Found” page with a link back to the dashboard.

## Conclusion and Overall App Journey
From the moment a new user lands on the welcome page to the daily routine of playing music, this application provides a smooth, clear path. The user opens the app, signs up or signs in, and lands on a personalized dashboard that showcases their favorite content and listening history. From there, they can browse, search, and play music with intuitive controls and persistent audio playback. If they need to update their profile or adjust preferences, the settings area handles it cleanly. Throughout the experience, error messages guide the user back on track in case of any mistakes or connectivity issues. At the end of each session, signing out is just one click away, ensuring security and peace of mind. This complete flow covers every key page and user journey step so that anyone can follow it from start to finish.
